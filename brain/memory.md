## 1. Project Context & Identity

- **Official Source of Truth:**
  - Problem Statement ID is **26251** (workspace folder name `sih251` is retained to preserve Git integrity).
  - Organization: Ministry of Defence (MoD) — Defence Services Staff College.
  - The challenge addresses difficulty in maintaining assured and timely logistics support to forward formations across dispersed, operationally challenging areas where demand forecasting, inventory levels, transportation capacity, terrain/weather, and consumption patterns are maintained across disparate information streams.
- **Product Name:** **LogiPredict AI**.
- **Prototype Nature:** An explainable, self-contained, decision-support prototype built by a student hackathon team using 100% synthetic, unclassified mock data.

---

## 2. Core Conventions & Governance

- **Documentation First:** All system designs, API schemas, and data structures must be documented in `brain/` before coding.
- **Strict Implementation Gate:** No application source code, UI components, or package installs until the user explicitly reviews and approves the documentation.
- **Zero Real Operational Data:** Strictly synthetic nodes (`Base Depot Alpha`, `Transit Hub Bravo`, `Forward Post Delta`), generalized commodities (`Class I Rations`, `Class III Fuel/POL`, `Medical`, `Spares`).
- **Core MVP vs. Proposed Extensions:** Core MVP focuses on Inventory, Forecasting, Run-Out Calculation, Replenishment, and Scenario Simulation. GIS mapping, weather factors, and mock IoT contracts are explicitly treated as proposed extensions.
